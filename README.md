# Розклад занять

Автоматичне складання розкладу (Google OR-Tools **CP-SAT**) без власного
сервера: дані — у Google Таблиці, збірка й публікація — на GitHub, сайт —
на GitHub Pages. Так само, як [latin-dictionary](https://github.com/kostyantynbalashov/latin-dictionary),
тільки джерело — Google Таблиця, а не файл у репозиторії (бо кілька людей
мають редагувати дані одночасно), і частина результату (навантаження,
картки викладачів) лишається приватною.

## Як це працює

```
Google Таблиця (редагують оператори) ──► GitHub Actions ──► build.py
                                                               │
                                     CP-SAT розставляє заняття │
                                                               ▼
                               site/data.js (публічно, GitHub Pages)
                               — розклад: дата, пара, дисципліна,
                                 ПІБ викладача, група, аудиторія

                               вкладка «Навантаження (авто)» у тій самій
                               Google Таблиці (приватно — лише ті, кому
                               ви дали доступ до таблиці)
                               — ставка, ступінь, звання, навантаження
```

Збірка запускається щодня автоматично (Пн-Пт) і вручну — кнопкою
"Run workflow" на вкладці **Actions** репозиторію.

## Налаштування (робиться один раз)

### 1. Google Таблиця

1. Відкрийте `data_samples/sample.xlsx` (у цьому репозиторії) і завантажте
   його в Google Drive: **Файл → Імпорт → Завантажити** → створити нову
   Google Таблицю.
2. Заповніть аркуші своїми даними (інструкція — на аркуші «Як заповнювати»).
3. Скопіюйте ID таблиці з адресного рядка:
   `docs.google.com/spreadsheets/d/`**`ЦЕЙ_ID`**`/edit`.

### 2. Службовий Google-акаунт (для GitHub Actions)

GitHub Actions має читати вашу таблицю й писати в неї (вкладку
«Навантаження») без вашого особистого логіну. Для цього:

1. [console.cloud.google.com](https://console.cloud.google.com) → створіть
   проєкт (або оберіть наявний).
2. **APIs & Services → Library** → знайдіть **Google Sheets API** → Enable.
3. **APIs & Services → Credentials → Create Credentials → Service Account**.
   Назва — будь-яка, напр. `timetable-bot`. Ролі не потрібні, Create and
   Continue → Done.
4. Відкрийте створений службовий акаунт → вкладка **Keys → Add Key → Create
   new key → JSON**. Завантажиться файл-ключ — **бережіть його як пароль**,
   нікому не показуйте й нікуди, крім GitHub-секретів (крок 4 нижче), не
   вставляйте.
5. Скопіюйте **email** службового акаунта (виглядає як
   `timetable-bot@ваш-проєкт.iam.gserviceaccount.com`).
6. У Google Таблиці (крок 1) → **Поділитися** → вставте цей email →
   доступ **Редактор** (потрібен, бо скрипт дописує вкладку «Навантаження»).

### 3. Секрети репозиторію на GitHub

Репозиторій → **Settings → Secrets and variables → Actions**:
- **New repository secret** `GOOGLE_SHEET_ID` — ID таблиці з кроку 1.3.
- **New repository secret** `GOOGLE_SERVICE_ACCOUNT_JSON` — весь вміст
  JSON-файлу з кроку 2.4 (відкрийте файл текстовим редактором, скопіюйте
  все, вставте сюди).
- (необов'язково) вкладка **Variables** → `WORKLOAD_NORM_HOURS` — реальна
  норма годин на ставку у вашому закладі (інакше береться орієнтовні 600).

### 4. GitHub Pages

Репозиторій → **Settings → Pages** → Source: **GitHub Actions**.

### 5. Перша збірка

Вкладка **Actions** → «Збірка і публікація розкладу» → **Run workflow**.
За хвилину-дві сайт зʼявиться за посиланням, яке GitHub покаже там-таки.

## Перевірка журналу збірки

Після кожного запуску на вкладці Actions, у кроці «Зібрати сайт…», видно
звіт: скільки занять розставлено, і зауваження — накладки аудиторій,
викладачів чи груп, нерозпізнані посилання, заняття, для яких забракло
аудиторій. Ті самі зауваження видно і на сайті, вкладка «Про збірку».

## Локальна перевірка (необов'язково)

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python data_samples/make_sample.py   # перегенерувати приклад
.venv/bin/python build.py                      # читає data_samples/sample.xlsx
```
Потім відкрити `site/index.html` у браузері (через `python -m http.server`
у теці `site`, бо `data.js` не завантажується з `file://`).

## Обмеження цієї версії

- **Стрічковий** розклад система підбирає сама (CP-SAT, без накладок).
  **Цикловий** і **довільний** — дату й аудиторію вказує оператор, система
  лише перевіряє накладки й попереджає.
- Навантаження — орієнтовний підрахунок контактних годин (1 пара = 2
  акад. год.), без поділу груп на підгрупи й методичного навантаження.
- Немає інтерактивних заявок від студентів/викладачів (на заміну пари
  тощо) — лише перегляд.
- Одночасне редагування Google Таблиці кількома операторами працює (на
  відміну від Excel-файлу в git), але якщо збірка запуститься посеред
  редагування — може підхопити незавершені зміни; тоді просто перезапустіть
  Actions вручну.

## Структура

| Файл / папка | Що це |
|---|---|
| `data_samples/sample.xlsx` | Шаблон для імпорту в Google Таблицю, з прикладом і інструкцією |
| `build.py` | Оркестратор: Таблиця → CP-SAT → `site/data.js` + приватне навантаження |
| `lib/sheet_source.py` | Читання Google Таблиці (або локального .xlsx) |
| `lib/domain.py` | Розбір рядків у викладачів/аудиторії/групи/заняття, з перевіркою |
| `lib/patterns.py` | Розбір «Тижні» / «Дати та пари» тощо в конкретні дати |
| `lib/scheduling.py` | CP-SAT для стрічкового розкладу + перевірка циклового/довільного |
| `lib/workload.py` | Підрахунок навантаження |
| `site/` | Статичний сайт (HTML/CSS/JS) |
| `.github/workflows/deploy.yml` | Автоматична збірка й публікація на GitHub Pages |
